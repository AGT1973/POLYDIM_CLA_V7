## **4. HALLAZGOS FUNCIONALES — evidencia, causa, mejor solución, test**

### **H1 🔴 — La compuerta de salida de Stiefel es la reencarnación exacta del hallazgo A2 de V761**

**Evidencia** (final de **`polydim\_stiefel\_cayley\_smw\_f64`**):

cpp


if (report) report-\>ortho\_err = err;

\}

return POLYDIM\_SUCCESS; // \<-- err se midió, se reportó... y se descartó


**Causa:** el comentario del propio código dice *"la compuerta nunca acepta algo peor de lo que declara"* — pero no hay compuerta. Si el pivote pasa y aún así la retracción produce **`max|YᵀY−I|`** roto (bug futuro, compilador distinto, tau patológico), el kernel devuelve SUCCESS. Es literalmente la enfermedad A2 de V761 ("acumuladores calculados y descartados") reaparecida en la salida en vez de la entrada.

**Solución (mejor):** aplicar la compuerta, con factor de absorción para no rechazar de salida a una X que apenas pasó de entrada (err\_salida ≈ err\_entrada + err\_retracción, y err\_entrada ya se admitió ≤ tol):

cpp


if (report) report-\>ortho\_err = err;

/\* V763 — compuerta de salida: medir sin aplicar era la enfermedad A2. \*/

if (err \> 2.0 \* tol.gram\_ortho) return POLYDIM\_ERR\_NUMERICAL\_INSTABILITY;

\}

return POLYDIM\_SUCCESS;


Margen medido: a D=65536,K=64, err=7.33e-15 vs 2·tol=7.2e-12 → **~1000× de holgura**, cero falsos positivos.

**Test:** extraé el chequeo a una función interna **`static double measure\_ortho\_err(const double\* Y, uint64\_t D, uint32\_t K, int nthreads)`** y unit-testeala con una Y saboteada (fila 0 escalada por 1+1e-9 → err≈1e-9 → la compuerta debe disparar). La V461 de V761 era "happy path sin adversario"; no repitas eso con la salida.


### **H2 🔴 — Aliasing en Stiefel: in-place corrompe en silencio**

**Evidencia** (loop final de Y):

cpp


for (uint32\_t p = 0; p \< K2; ++p) \{

const double w = (p \< K) ? gi\[p\] : xi\[p - K\]; // \<-- xi\[p-K\] se lee DESPUÉS

...

for (uint32\_t k = 0; k \< K; ++k) yi\[k\] += s \* Zp\[k\]; // \<-- de que p anteriores

\} // ya escribieron yi\[k\]


**Causa:** **`polydim\_rodrigues\_geodesic\_f64`** **sí** valida **`overlaps(y\_out, u/v)`**; Stiefel no valida nada. Con **`Y\_out==X`**: en p=K, **`xi\[0\]`** ya fue modificado por el k-loop de p=0. Con **`Y\_out==G`**: en p=1, **`gi\[1\]`** ya fue modificado por el k-loop de p=0. En ambos casos: **números erróneos con rc=SUCCESS**. Y el in-place es un caso de uso *real* a D=10⁶, K=64 (duplicar el buffer de salida cuesta 512 MB extra).

**Solución (mejor — no rechazar, habilitar):** cada fila de salida depende **solo** de la fila i de X y de G (Yᵢ = Xᵢ + τ·\[Gᵢ Xᵢ\]·Z). Staging por fila en stack:

cpp


/\* V763 — staging por fila: habilita in-place Y\_out==X / Y\_out==G sin aliasing. \*/

\#pragma omp parallel for num\_threads(nthreads) schedule(static)

for (int64\_t i = 0; i \< static\_cast\<int64\_t\>(D); ++i) \{

const double\* xi = X + static\_cast\<size\_t\>(i) \* K;

const double\* gi = G + static\_cast\<size\_t\>(i) \* K;

double\* yi = Y\_out + static\_cast\<size\_t\>(i) \* K;

double xr\[POLYDIM\_MAX\_K\], gr\[POLYDIM\_MAX\_K\]; /\* 8 KB de stack por hilo \*/

for (uint32\_t k = 0; k \< K; ++k) \{ xr\[k\] = xi\[k\]; gr\[k\] = gi\[k\]; \}

for (uint32\_t k = 0; k \< K; ++k) yi\[k\] = xr\[k\];

for (uint32\_t p = 0; p \< K2; ++p) \{

const double w = (p \< K) ? gr\[p\] : xr\[p - K\];

if (w == 0.0) continue;

const double s = tau \* w;

const double\* Zp = Z.data() + static\_cast\<size\_t\>(p) \* K;

for (uint32\_t k = 0; k \< K; ++k) yi\[k\] += s \* Zp\[k\];

\}

\}


Alternativa mínima si preferís rechazar: **`overlaps`** con **`D·K·sizeof(double)`** (con guard de overflow, ver H16) → **`POLYDIM\_ERR\_ALIASED\_BUFFERS`**. Pero el staging es mejor: cuesta ~nada y da in-place gratis.

**Test:** llamar con buffer separado, con **`Y\_out==X`** y con **`Y\_out==G`**; los tres resultados deben ser **bit-idénticos**. Hoy este test falla — eso documenta el bug.

### **H4 🟠 — Una tolerancia NaN apaga todas las compuertas en silencio**

**Evidencia:** **`e\_yy \> tol.point\_norm`** con **`tol.point\_norm = NaN`** es **false** ⇒ **`POINT\_OFF\_MANIFOLD`** jamás se dispara. Igual para **`basis\_ortho`** (3 compuertas) y **`gram\_ortho`**. Asimetría peligrosa: NaN en **`pivot\_rel`** hace fallar **todo** (**`!(best \> NaN)`** = true ⇒ siempre INSTABILITY — dirección segura), pero NaN en los demás **apaga** los gates (dirección insegura). Un caller que construye **`PolydimTolerances`** a mano y deja un campo sin inicializar en NaN desactiva el producto entero sin enterarse.

**Solución** (barato, al entry, antes de cualquier región paralela):

cpp


static int32\_t validate\_tolerances(const PolydimTolerances& t) \{

const double f\[4\] = \{ t.basis\_ortho, t.point\_norm, t.gram\_ortho, t.pivot\_rel \};

for (int i = 0; i \< 4; ++i)

if (!std::isfinite(f\[i\]) || !(f\[i\] \> 0.0)) return POLYDIM\_ERR\_INVALID\_SCALAR;

if (t.reject\_subnormal != 0 && t.reject\_subnormal != 1)

return POLYDIM\_ERR\_INVALID\_SCALAR;

return POLYDIM\_SUCCESS;

\}


Llamar en **`rodrigues`** y **`stiefel`** inmediatamente después de resolver el default. V762 valida los datos pero no valida **al validador** — y el validador es el producto.

**Test:** tol con **`point\_norm=NaN`** → rechazo; tol con **`basis\_ortho=-1`** → rechazo.

### **H7 🟡 — Criterio de pivote divergente entre ruta nativa y ruta BLAS**

**Evidencia:** la ruta nativa compara el **pivote de eliminación real** (**`best`**, el máximo de columna en cada paso). La ruta BLAS compara **`min|U\_kk|`** **después** de que **`dgesv`** destruyó **`Mc`** con los factores LU — que es otra magnitud. Mismo (X, G, tau) puede pasar la compuerta en nativo y fallar en BLAS o viceversa. Para una "implementación de referencia" certificadora, dos criterios de aceptación distintos según el flag de compilación es una especificación ambigua.

**Solución:** en la ruta BLAS, capturar los pivotes reales no es posible vía **`dgesv`** (LAPACK no los expone). Opciones honestas: (1) calcular **`min|U\_kk|`** también en la ruta nativa y **unificar el criterio** en min|U\_kk| (es el proxy estándar de LINPACK, y lo tenés gratis en ambas rutas: en nativa, después de la eliminación leés la diagonal de M); (2) o documentar explícitamente que el umbral certifica magnitudes distintas por ruta. Recomiendo (1): dos líneas.


### **H8 🟡 — PMTP: misuse de la API produce desgarro NO detectado**

**Evidencia:** **`begin\_write`** hace **`slot\_seq\[slot\].fetch\_add(1)`** sin verificar que el slot esté **par**. Si el (único) escritor llama **`begin\_write`** dos veces sin commit — API misuse, pero el contrato del header no lo impide — la segunda llamada pasa el seq de impar (1) a **par (2) mientras se escribe**. Un lector que valide ticket=2 con el payload a medio escribir obtiene **SUCCESS con datos desgarrados**. Análogo: **`commit\_write`** sobre un slot sin begin deja el seq **impar** (parece "escribiendo") y corrompe el estado.

**Solución (dos líneas de guard, single-writer reforzado):**

cpp


/\* en begin\_write, antes del fetch\_add: \*/

if (c-\>slot\_seq\[slot\].load(std::memory\_order\_relaxed) & 1ull)

return POLYDIM\_ERR\_SEQLOCK\_RACE; /\* doble begin: misuse detectado \*/


/\* en commit\_write, antes del fence: \*/

if (!(c-\>slot\_seq\[slot\].load(std::memory\_order\_relaxed) & 1ull))

return POLYDIM\_ERR\_SEQLOCK\_RACE; /\* commit sin begin: misuse detectado \*/


**Test:** **`begin;begin`** → segundo devuelve -6; **`commit`** sin begin → -6.


### **H9 🟡 — PMTP: semántica de entrega imprecisa (skip-on-race y duplicados)**

**Evidencia (trazado):**

1. **`acquire\_read`** hace **`\*observed\_seq = gs`** **antes** de que el lector copie el payload. Si **`validate\_read`** devuelve RACE, ese gs quedó consumido para siempre: el lector **nunca** puede reintentar ese snapshot (avanza al siguiente).

2. Existe una ventana donde el lector carga **`published=(g,P)`**, el escritor completa g+1 y g+2 en otras ranuras y reabre P, y el ticket que el lector lee corresponde al commit **más nuevo**: valida bien, pero registra **`observed=g`** con datos de **`g+2`**. Resultado: ese update se entrega **dos veces** (duplicado). Nunca hay desgarro (verificado en V8), pero la semántica exacta no está documentada en ninguna parte.

**Solución:** documentar en el header la semántica real — *"snapshots coherentes, at-least-once, duplicados posibles, gs saltados tras RACE"* — y el patrón rollback que recupera el retry:

c


uint64\_t prev = obs;

if (polydim\_pmtp\_acquire\_read(&c, &obs, &slot, &tk) == 1) \{

memcpy(dst, slots + slot \* SZ, SZ);

if (polydim\_pmtp\_validate\_read(&c, slot, tk) != POLYDIM\_SUCCESS)

obs = prev; /\* rollback: reintenta el mismo o un gs más nuevo \*/

\}


Verifiqué que el rollback es seguro: un RACE implica que el escritor ya avanzó **`published`** más allá de (g,P), así que el reintento nunca se cuelga en datos viejos. Para deduplicar de verdad, el gs debe viajar **en el payload** (el caller lo conoce leyendo su propia variable **`obs`** tras un acquire exitoso — documentalo).


### **H10 ⚪/FORMAL — PMTP: data race formal C++11 sobre el payload**

**Evidencia:** el payload se copia con lecturas planas (contrato del header: "copiar payload\[slot\]") mientras el escritor puede estar escribiéndolo con stores planos. Eso es **data race = UB** según el estándar C++11 (§intro.races), aunque con los fences actuales y en x86-64 TSO funcione perfectamente — es el mismo estatus formal que tienen los seqlocks del kernel de Linux (que son C/asm, no C++11). Para un dossier cuyo lema es rigor formal, este punto **debe** aparecer declarado, no descubierto por el próximo auditor.

**Solución:** una de dos, explícita:

- **(a)** Contrato documentado: "payload debe accederse con loads/stores **`memory\_order\_relaxed`** atómicos o en plataformas con TSO; alineación ≥ **`alignof(double)`**" — y ofrecer **`polydim\_pmtp\_snapshot\_f64()`** en la biblioteca que encapsula acquire→copy→validate con el rollback de H9, para que la disciplina no dependa del caller.

- **(b)** Aceptar y documentar el memory model objetivo (kernel-style), citando la limitación.

### **P3 🟡 \[TEORÍA ESTÁNDAR + MEDIR\] — El Gram no usa FMA: pagas el doble de redondeos y la mitad del throughput por nada**

### **P5 🔴 \[DERIVADO\] — El resultado depende de `OMP\_NUM\_THREADS`: el kernel no es reproducible bit a bit**

**Evidencia.** Los parciales Neumaier por hilo se fusionan **`for t in 0..nthreads`**. El comentario de **`polydim\_cdot`** dice *"reproducible entre ejecuciones"* — **solo es verdad a número de hilos fijo**, y el número de hilos lo decide una variable de entorno. Para un kernel cuyo producto es *certificación*, que el certificado dependa de **`OMP\_NUM\_THREADS`** es un agujero estructural. **Solución — partición por bloques de datos, no por hilos.** La reproducibilidad no necesita acumuladores exactos (Kulisch/superacumulador, Rump–Ogita–Oishi, ReproBLAS — la artillería pesada, necesaria solo si querés bitwise **cross-ISA**); necesita que **la partición y el orden de fusión sean función de los datos, no del scheduler**:

/\* P5 — reducción determinista: cada bloque de 4096 elementos produce el MISMO

\* parcial Neumaier sin importar qué hilo lo compute, y la fusión sigue el

\* orden de índice de bloque, no el de tid. Resultado: bitwise idéntico para

\* cualquier OMP\_NUM\_THREADS. Memoria extra: (D/4096)\*16 bytes = 39 KB a D=1e7. \*/

constexpr uint64\_t BLK = 4096;

const uint64\_t nb = (D + BLK - 1) / BLK;

std::vector\<Neumaier\> blk;

try \{ blk.assign(nb, Neumaier\{\}); \} catch (const std::bad\_alloc&) \{ /\* H5 \*/ \}

\#pragma omp parallel for num\_threads(nthreads) schedule(static)

const uint64\_t hi = std::min(lo + BLK, D);

\}

for (uint64\_t bi = 0; bi \< nb; ++bi) total.merge(blk\[bi\]); /\* orden fijo \*/

return total;

\}

### **P8 🟠 \[TEORÍA ESTÁNDAR\] — Una sola retracción = un solo punto de fallo. SOTA = polimorfismo de retracciones**

## **§4 — C3/C4/C5/C6/C7: refinamientos de contrato, dos de ellos auto-correcciones**

### **C3 🟡 — PMTP: la semántica real es "broadcast de último estado", y eso hay que declararlo**

Retrazé el protocolo completo del triple búfer con el lector leyendo **`published=(g,P)`** y el escritor avanzando libremente:

- **Gaps por lector:** si el escritor completa g+1, g+2 y reabre P mientras el lector carga el ticket, el lector ve ticket impar (→ "sin novedad" **sin consumir** observed\_seq) o ticket par del commit g+3 (→ entrega datos de g+3 registrando observed=g). En ambos caminos **g+1 y g+2 jamás se entregan a ese lector**.

- Mi R1-H9 llamó a esto "at-least-once" — **mal calificado**. La semántica real: *snapshots monottes, latest-wins, gaps posibles, re-entrega benigna tras rollback*.

- **Y aquí está el giro que importa:** para un bus de **tensores latentes** (el propósito declarado de PMTP: los agentes leen "el estado actual del tensor"), latest-wins **es la semántica correcta**. Gaps no son un bug — serían un bug si PMTP fuera una cola de eventos, que no es.

**Fix:** un párrafo de contrato en el header que hoy no existe:

c


/\* SEMÁNTICA DE ENTREGA (leer antes de usar):

\* PMTP es un BROADCAST DE ÚLTIMO ESTADO, no una cola de eventos.

\* - Cada acquire entrega el commit más reciente publicado.

\* - Commits intermedios pueden no entregarse nunca (latest-wins).

\* - Tras SEQLOCK\_RACE, restaurar observed\_seq al valor previo reintenta

\* con estado más nuevo (nunca más viejo).

\* - Si necesitás secuenciamiento (eventos, deltas), versioná el payload:

\* el escritor debe incrustar su propio contador monótono DENTRO del

\* payload; el lector lo compara con el último procesado. \*/


Esto además explica por qué la cifra "218,417 lecturas validadas" (H11) es inverificable: sin versionado en payload, "lectura válida" ni siquiera tiene definición operativa precisa entre lecturas saltadas y entregadas.

## **§5 — SOTA NUMÉRICO: DEL CERTIFICADO AL RECINTO VERIFICADO**

### **S1 — Formalizar P11 como enclosure (recinto): la compuerta se vuelve una prueba**

P11 (ronda 2) reportaba una cota. El peldaño industrial superior es el **recinto**: no "el error fue ≤ X", sino "el valor exacto está contenido en \[lo, hi\], demostrado por la aritmética de esta llamada". La diferencia es jurídica: una medición convence; un recinto **certifica**.

\* donde Sabs = Σ|a\_i·b\_i| (acumulador plano en el MISMO barrido:

\* vectorizable, costo ~0 frente al Neumaier).

\* Referencias: Neumaier 1984; Higham, ASNA §4.2 (error en curso);

\* la forma gamma es el resultado clásico de Wilkinson. \*/

### **S1b — TwoProd vía FMA: el escalón Ogita–Rump–Oishi (elimina el término γ)**

El término γ\_D del recinto es el pecado de los **productos** redondeados. Con FMA hardware (dispatch de P3), el error de cada producto se obtiene **exacto**:

\* p = a\*b; e = fma(a, b, -p); // e = error EXACTO del producto

\* el recinto colapsa a |c\_p| + |c\_e| + O(eps^2) — la clase exBLAS/

inline void twoprod\_fma(double a, double b, double& p, double& e) \{

p = a \* b;

e = std::fma(a, b, -p);

\}

### **S5 — Roofline exacto + chequeo de integridad por doble computación \[DERIVADO\]**

Bytes mínimos por llamada de Rodrigues: pasada 1 lee y,u,v (24D bytes), pasada 2 lee y,u,v y escribe y\_out (32D), pasada 3 lee y\_out (8D) → **64D bytes**.

| D | Tráfico | Piso @ 40 GB/s | Medido V762 | Lectura |
| - | - | - | - | - |
| 10⁶ | 64 MB | 1.6 ms | 4.27 ms | **2.7× de margen — hoy es latency-bound (consistente con P2), no bandwidth-bound** |
| 10⁷ | 640 MB | 16 ms | — | régimen bandwidth: P6 (THP) y stores no-temporales se vuelven obligatorios, no opcionales |

Y el regalo algebraico: la norma de salida **se puede computar sin la tercera pasada**, porque todo sale de los acumuladores de la pasada 1:

∥yout​∥2=⟨y,y⟩+2α⟨y,u⟩+2β⟨y,v⟩+α2⟨u,u⟩+β2⟨v,v⟩+2αβ⟨u,v⟩

Identidad exacta en reales (expansión bilineal). **Pero no la uses para reemplazar la medición — usala para contradecirla:** computá ambas. La medida captura el redondeo real; la algebraica es independiente de la memoria. Si difieren más allá de O(eps), **hubo corrupción de memoria o aliasing** (clase H2) — y el kernel acaba de detectarlo solo. Dos computaciones independientes del mismo invariante que se auditan mutuamente: eso es un chequeo de integridad de grado industrial, y cuesta ~cero porque reutiliza la pasada 1.


## **§7 — EL SILICIO QUE VIENE (sin mistificarlo)**

- **Heterogeneidad P/E-cores y sockets múltiples:** el número de hilos disponibles varía **en runtime** → el determinismo por partición de bloques (P5) pasa de buena práctica a requisito de diseño. Cada año más, no menos.

- **RISC-V (RVV):** longitud de vector **definida en runtime** — la fusión por carriles de P2 con ancho fijo 8 no es portable ahí; la partición en bloques de 4096 de P5 **sí** (el bloque es independiente del ancho). La decisión de diseño de P5 quedó validada por una arquitectura que aún no corrés: eso es diseñar para 2050.

- **AVX10:** convergencia del ISA vectorial de Intel — el dispatch runtime de P2/P3 sobrevive intacto; los atributos target se actualizan sin tocar la lógica.

- **AMX (Sapphire Rapids):** tiles para BF16/FP16/INT8 — **no aplica** a tus kernels FP64. Lo digo explícito para que nadie te lo venda: Stiefel doble precisión no tiene aceleración AMX; la vía es tensor-core FP64 de clase datacenter o CPU.

- **CXL / memoria en pools:** tu PMTP de punteros por memoria compartida es la arquitectura nativa de esa década — con la salvedad de C5 (alineación) y de que acquire/validate cruzando un link CXL necesita considerar latencia de coherencia: el ticket seqlock sigue siendo la primitiva correcta, el presupuesto de reintentos cambia.
